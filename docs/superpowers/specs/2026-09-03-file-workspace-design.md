# 文件工作区设计

## 目标

在现有 LAN Terminal 网页中增加受限的文件工作区，让同一可信局域网内的用户远程浏览 `ALLOWED_ROOT`（默认 `terminal-workspace`）及其子目录，并完成文件预览、下载、上传、重命名、删除和新建文件夹。它与网页终端共用一个 Express 服务和一个访问地址，不启动独立的文件共享服务。

## 范围与权限边界

- 文件工作区仅允许访问 `ALLOWED_ROOT` 的真实路径及真实子路径，不暴露项目源码、`.env`、`.git` 或工作区外的文件。
- 普通模式下文件操作不需要管理员密钥，沿用当前“可信局域网、无需普通登录”的使用模式。
- 管理员解锁仅用于已有的任意目录终端和目录选择能力，不扩大文件工作区的根目录范围。
- 每次读取和写入都对请求的相对路径做规范化、真实路径和根目录归属校验，拒绝 `..`、绝对路径、越界链接、无效路径和非法条目名称。
- 删除仅允许文件或空文件夹。删除非空文件夹必须失败，不递归删除目录。
- 重命名和新建文件夹只接收一个条目名称，拒绝路径分隔符、`.`、`..`、空白名称和 Windows 非法名称；重名时返回冲突错误。

## 服务端架构

在现有 Express 应用中增加独立的 `server/workspace-files.js` 模块，并由 `server/app.js` 以 `/api/workspace` 前缀挂载路由。该模块负责路径解析、目录列举、文件流、上传和写操作；终端 WebSocket 和会话管理不承担文件传输职责。

文件模块复用 `config.allowedRoot`，并抽取或复用与 `resolveWorkingDirectory` 等价的真实路径边界检查。对于读取已有对象，先使用 `realpath` 验证目标位于工作区内；对于创建目标，先校验其父目录的真实路径位于工作区内，再组合经过验证的单一名称。这样既禁止路径遍历，也阻止通过工作区内符号链接访问根目录外对象。

## HTTP 接口

所有业务路径均是相对于 `ALLOWED_ROOT` 的路径；根目录以 `.` 表示。失败响应均为 JSON：`{ "error": "面向用户的中文错误说明" }`。

### 目录内容

`GET /api/workspace/tree?path=.` 返回当前目录、父目录和直接子项。每个子项提供名称、相对路径、`directory` 或 `file` 类型、文件大小和修改时间；符号链接、无权限项目、无法规范化的项目和根外链接不返回。目录和文件分别以中文本地化自然顺序排序，单次响应最多 500 项。

### 内容预览与下载

`GET /api/workspace/content?path=<file>` 验证该目标为工作区内普通文件后，以流式响应发送内容。`download=1` 时设置安全的附件下载响应头；否则根据 MIME 类型以内联方式发送，使浏览器能够预览文本、图片、PDF、音频和视频。未知格式仍可下载。

### 上传

`POST /api/workspace/upload` 接受 `multipart/form-data`，表单包含目标目录路径和一个或多个文件。服务端限制单文件最大 2GB，使用流式 multipart 处理并直接写入临时文件，成功后原子移动到目标目录，避免大文件进入 Node.js 内存。上传文件名只取校验后的基础名称；如果同名存在，则自动生成不冲突的新名称。单个文件失败不会使已成功的其他文件回滚，响应会逐项返回成功、自动改名和失败结果。

### 新建、重命名与删除

- `POST /api/workspace/folders` 接收父目录路径和新文件夹名称，在已验证的父目录中新建文件夹。
- `PATCH /api/workspace/entries` 接收现有相对路径和新名称，在同一父目录内重命名。目标已存在时返回 HTTP 409。
- `DELETE /api/workspace/entries?path=<entry>` 删除一个工作区内文件或空文件夹。非空文件夹返回 HTTP 409，且绝不递归删除。

写操作成功后返回操作结果与规范化后的相对路径，供页面刷新和继续选中目标。

## 页面与交互

终端页面提供明确的“文件”入口；点击后导航到独立的 `/files.html` 文件工作区页面，避免与终端会话状态混在同一页面。文件工作区使用左侧目录树布局：左栏可展开目录，右栏显示当前路径导航、操作工具栏、文件列表和预览区域；页面提供“← 终端”按钮返回终端页面。

- 左侧目录树从工作区根开始按需加载，保留用户的展开状态；根目录显示为“工作区”，不显示服务器绝对路径。
- 右侧工具栏提供上传、新建文件夹和刷新。文件夹单击进入，文件单击选中并在预览区域打开。
- 选中条目的下载、重命名、删除置于条目操作区。删除前的确认对话框会显示目标名称；删除成功后目录与树节点刷新。
- 上传支持点击选择与拖放、多文件顺序上传、单项进度和逐项结果。冲突文件自动改名后，界面显示最终名称。
- 文本、图片、PDF、音视频优先使用浏览器原生预览。DOC/DOCX 使用客户端文档解析策略，XLS/XLSX 使用客户端表格解析策略；PPT/PPTX 和其他 Office 格式不承诺浏览器内预览，统一保留下载入口。预览库加载失败、格式不支持或文件不适合预览时，仅显示文件信息与下载入口。
- 在手机屏幕上，目录树切换为可开合面板；文件列表保持可用；预览以全屏抽屉打开，避免与列表产生重叠。

所有网络和操作失败使用页面内提示条展示，保留当前页面状态和可重试操作，不跳转到独立的错误页面或使用原生 `alert`。

## 数据流

1. 打开文件视图时，客户端请求根目录 `tree`，渲染根节点和根目录内容。
2. 用户展开树节点或进入目录时，请求对应目录的 `tree`；刷新只重新请求当前目录，保留树展开状态。
3. 用户选择文件时，客户端根据类型构建受限 `content` URL 进行预览；下载使用相同接口和 `download=1`。
4. 上传、新建目录、重命名或删除成功后，客户端重新加载当前目录和受影响的父目录树节点；失败时只显示错误，不推测服务端状态。

## 错误处理与资源限制

- 路径越界、链接越界、对象不存在、对象类型不匹配和非法名称返回 HTTP 400 或 404，且不泄漏绝对路径。
- 写入冲突和非空目录删除返回 HTTP 409；超过单文件上传上限返回 HTTP 413。
- 文件系统无权限、流读取失败和意外 I/O 错误记录在服务端，浏览器只收到通用且可理解的错误说明。
- 所有文件响应采用流式读取；上传暂存文件在失败、超限、断开和写入错误时清理。
- 文件列表限制为 500 项，避免大目录造成过大的响应和渲染负担。

## 验证

- 服务端单元与集成测试覆盖：根目录和子目录列举、排序和 500 项上限、普通文件元数据、绝对路径/`..`/根外链接拒绝。
- 测试内容读取与下载响应头、文本和二进制流、文件不存在或目录误作文件读取的错误响应。
- 测试新建目录、合法重命名、名称冲突、文件删除、空目录删除和非空目录删除拒绝。
- 测试多文件上传、同名自动改名、非法文件名、目标目录无效、超过 2GB 的请求拒绝，以及上传失败后的暂存文件清理。
- 浏览器验收覆盖：目录树展开与保持、路径导航、预览、下载、拖放/选择上传、进度和结果、重命名、删除确认、新建文件夹以及主要错误提示。
- 在桌面和 375px 宽度下检查目录树、操作栏、文件列表和全屏预览不重叠，且主要操作可访问。

## 非目标

- 不提供工作区外的文件访问，也不因管理员解锁而开放该能力。
- 不实现递归删除、文件内容编辑、版本历史、跨设备账户体系、公开网络认证或另起文件共享服务。
