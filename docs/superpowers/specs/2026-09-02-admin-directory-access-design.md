# 管理员目录访问设计

## 目标

普通用户只能从项目内独立的 `terminal-workspace` 目录创建终端；管理员在输入应用密钥并解锁后，可在网页内浏览服务进程所属 Windows 账号有权限访问的任意目录。

## 权限模型

- 普通模式不接受绝对路径，目录接口和终端创建均复用受限根目录校验。
- 管理员解锁通过 `POST /api/admin/unlock` 完成，成功后签发内存中的短时不透明令牌，默认 15 分钟有效。
- 令牌绑定当前浏览器的客户端 ID，只保存在当前页面 JavaScript 内存，不写入 `localStorage`。
- 管理员目录请求和管理员终端创建都必须携带有效令牌；令牌失效后回到普通模式。
- 密钥比较使用固定长度哈希后的时间安全比较，失败请求按客户端地址限流。
- 管理员权限不会提升 Windows 账号权限，无法访问运行服务的 Windows 账号本身无权访问的目录。

## 数据流

1. 页面用现有客户端 ID 和 `ADMIN_KEY` 调用解锁接口。
2. 服务端验证密钥，记录令牌过期时间和客户端 ID，返回令牌及过期时间。
3. 目录浏览请求用 `X-Admin-Token` 与 `X-Client-ID` 请求头；普通请求继续只传相对路径。
4. 创建终端的 WebSocket `create` payload 可携带内存令牌。服务端在创建 PTY 前验证令牌，并选择受限或管理员目录解析器。

## 错误处理

- 未配置管理员密钥时，解锁返回 404，避免暴露管理员功能是否启用。
- 密钥错误返回 401；短时间内超过失败上限返回 429。
- 过期或不匹配的令牌返回 401，不降级为管理员目录访问。
- 越界、不存在或非目录路径返回 400，响应不向普通用户泄露绝对路径。

## 验证

- 默认/显式普通根目录始终是项目下的 `terminal-workspace`，项目源码目录不可列出。
- 管理员正确密钥可解锁并浏览绝对路径，错误密钥、过期令牌和错误客户端 ID 均失败。
- 管理员创建的终端使用选定绝对工作目录；普通终端仍拒绝绝对路径。
- HTTP 与 WebSocket 两条路径均覆盖授权测试，完整测试套件通过。
