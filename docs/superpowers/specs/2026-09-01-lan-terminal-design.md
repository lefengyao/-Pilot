# 局域网网页终端设计规格

## 1. 目标与范围

构建一个运行在 Windows 主机上的局域网 Web 应用，让内网浏览器通过网页查看并交互操作本机的 PowerShell 或 CMD。

本期范围：

- 通过浏览器创建 PowerShell 或 CMD 会话。
- 每个浏览器连接拥有隔离的会话空间，可创建多个独立进程。
- 实时显示终端输出，支持键盘输入、ANSI 颜色、光标行为和终端尺寸同步。
- 浏览器刷新或关闭后保留进程；用户可以通过会话 ID 重新连接。
- 手动停止、重启会话，以及服务器重启时清理全部进程。
- 面向可信局域网，无登录认证。

不在本期范围：公网部署、多用户账号、命令审计、文件上传下载、权限提升、跨主机终端代理。

## 2. 方案选择

采用 Node.js + Express + WebSocket + `node-pty` + xterm.js。

`node-pty` 能在 Windows 上创建真正的伪终端，保留交互式程序、颜色和控制序列；WebSocket 适合低延迟双向传输；xterm.js 负责浏览器端终端渲染。Python 方案的 Windows PTY 适配和部署成本更高；HTTP 命令轮询无法提供完整的交互式终端体验，因此不采用。

## 3. 系统架构

### 3.1 服务端

- Express 提供静态资源、健康检查和基础配置读取。
- WebSocket 服务负责浏览器连接和终端事件传输。
- `SessionManager` 管理会话注册表、生命周期、并发限制和回收。
- `TerminalSession` 封装一个 `node-pty` 进程，负责输入、输出、resize、停止、重启和状态转换。
- 会话状态保存在内存中；服务器重启后不恢复旧会话。

服务默认绑定局域网网卡，端口和允许的工作目录由配置指定。服务不开放公网认证，部署前必须确认网络边界。

### 3.2 浏览器端

- xterm.js 创建终端实例并处理输入、输出和尺寸变化。
- 会话状态管理器维护当前浏览器创建的会话列表和选中项。
- WebSocket 客户端负责连接、重连、消息校验和错误提示。
- 会话列表、终端工具栏、新建会话表单和风险提示组成主工作台。

## 4. 数据流与消息协议

浏览器创建会话时发送 `create`，包含 Shell 类型、会话名称和初始工作目录；服务端校验配置和资源限制后创建 PTY，并返回会话 ID。PTY 输出按批次发送 `output` 消息，浏览器直接交给 xterm.js 渲染。键盘输入发送 `input`，终端尺寸变化发送 `resize`。停止和重启分别发送 `stop`、`restart`。服务端通过 `status` 广播状态转换，通过 `error` 返回可读错误。

每条消息包含 `type`、`sessionId` 和对应 `payload`。服务端拒绝未知类型、缺少会话 ID 或超出长度上限的消息。

WebSocket 断开时，服务端解除当前连接与会话的控制关系，但不结束 PTY；重新连接时根据会话 ID 恢复输出订阅。会话历史保存有限长度的内存环形缓冲，避免无限增长。

## 5. 界面与交互

打开页面即进入深色终端工作台：

- 左侧会话栏显示新建按钮、Shell 类型、状态、创建时间和简短 ID。
- 主区顶部显示当前 Shell、连接状态、工作目录和 PID。
- 中间显示 xterm.js 终端。
- 工具栏提供停止、重启、清空和重新连接操作；停止需要确认。
- 新建会话表单允许选择 PowerShell/CMD、工作目录和名称。
- 状态包括连接中、运行中、已断开、已退出和错误。
- 移动端将会话栏收缩为抽屉，终端占满可用宽度。
- 页面固定显示“无认证，命令以服务运行账号权限执行”的风险提示。

## 6. 错误处理与资源策略

- 默认每个 WebSocket 连接最多 8 个会话，服务器总会话上限可配置。
- 每个会话的历史输出和待发送输出使用有界缓冲；输出过快时批量发送并丢弃超出上限的最旧历史，不阻塞 PTY。
- Shell 启动失败、工作目录无效、PTY 错误、连接断开和进程异常退出均转换为状态或错误消息，不使 Node.js 进程崩溃。
- 服务器收到关闭信号时停止接受新会话，通知浏览器并回收全部子进程。
- 用户输入原样写入 PTY，不拼接额外命令。工作目录只允许位于服务配置的允许目录内。
- 日志仅记录会话生命周期、连接和错误，不记录命令内容。

## 7. 安全边界与部署假设

应用采用可信局域网模式，不做登录认证。任何能访问监听地址和端口的设备都能执行服务运行账号拥有的命令，因此服务不得暴露到公网，且不应以管理员账号运行。部署说明需要包含监听地址、Windows 防火墙端口规则、允许目录、并发上限和风险提示。

## 8. 验证计划

### 单元测试

- 会话创建、状态转换、停止和重启。
- 每连接和全局并发上限。
- 非法消息、无效工作目录和资源清理。

### WebSocket 集成测试

- 输入/输出回环。
- resize 事件。
- 断线重连和历史输出恢复。
- PTY 异常退出和服务关闭。

### 浏览器冒烟测试

- 创建 PowerShell 与 CMD。
- 同一浏览器创建多个隔离会话。
- 实时输出、清空、停止、重启和重新连接。
- Windows 10/11、中文路径、ANSI 颜色、长时间运行命令和服务器重启。

## 9. 验收标准

1. 在同一局域网的另一台浏览器打开服务地址即可使用，无需额外客户端。
2. PowerShell 和 CMD 均能执行交互式命令并实时显示输出。
3. 不同会话的输入、输出和进程互不混淆。
4. 刷新页面后可通过会话列表重新连接仍在运行的进程。
5. 停止、重启、异常退出和服务器关闭都能回收资源并给出明确状态。
6. 超出资源上限或发送非法消息不会导致服务崩溃。
