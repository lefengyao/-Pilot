# 网页目录选择器设计

## 目标

在“新建终端”流程中提供一个完全在网页内运行的初始工作目录选择器。用户可在服务配置的 `ALLOWED_ROOT` 下浏览目录并选择当前目录，不调用 Windows 资源管理器，也不显示允许目录之外的路径或文件。

## 范围

- 将新建终端表单中的 `cwd` 改为只读的已选目录显示，并提供“选择目录”按钮。
- 打开独立的网页目录选择弹窗，支持显示当前位置、进入直接子目录、返回上级、取消和确认当前目录。
- 目录列表仅显示允许目录内的直接子目录，按中文本地化排序，单次最多返回 500 项。
- 选择器中的路径始终是相对于 `ALLOWED_ROOT` 的路径；允许目录根在界面中显示为“允许目录”。
- 终端创建继续使用现有 `resolveWorkingDirectory` 做最终路径验证。

不在范围内：文件选择、文件上传下载、创建/删除/重命名目录、在浏览器中输入任意绝对路径、调用资源管理器。

## 服务端接口

新增同源接口：`GET /api/directories?path=<相对路径>`。

- 未提供 `path` 或使用 `.` 时返回允许目录根。
- 服务端使用与终端创建相同的 `resolveWorkingDirectory(allowedRoot, path)` 解析当前目录；无效路径、`..` 越界和真实路径离开根目录的链接均返回 HTTP 400。
- 服务端读取当前目录的直接子项，只返回真实路径仍位于允许目录内的目录。普通文件、无权限或无法解析的子项不返回。
- 响应不返回服务器绝对路径，格式为：

```json
{
  "path": "projects\\pilot",
  "parent": "projects",
  "directories": [
    { "name": "api", "path": "projects\\pilot\\api" },
    { "name": "web", "path": "projects\\pilot\\web" }
  ]
}
```

- 在根目录响应中，`path` 为 `.`，`parent` 为 `null`。
- 未处理错误返回 HTTP 500 及通用错误消息，不将目录详情或堆栈返回浏览器。

## 网页交互

1. 用户点击“新建终端”。初始目录显示为“允许目录”，对应 `cwd: "."`。
2. 用户点击“选择目录”，网页打开目录选择弹窗并请求根目录列表。
3. 点击子目录后，弹窗请求并显示该目录的直接子目录；顶部显示“允许目录 / 子目录 / …”。
4. 点击“上一级”回到 `parent`，在根目录时该控件禁用。
5. 点击“使用当前目录”后，弹窗关闭，表单的只读目录字段更新为相对路径；后续创建消息沿用该值。
6. 点击“取消”时不修改表单中原有选择。
7. 请求失败时，在目录选择弹窗中显示简短错误并保留当前选择，用户可重试或取消。

移动端目录弹窗高度受视口约束，目录列表独立滚动，顶部路径和底部操作始终可见。

## 安全与资源边界

- 浏览接口仅是 `ALLOWED_ROOT` 内的目录枚举；它不是操作系统文件选择器，也不扩大 PowerShell/CMD 本身的账号权限。
- 响应仅传递相对路径，不泄漏 `ALLOWED_ROOT` 的绝对路径。
- 每个请求重新进行真实路径检查，避免请求参数或链接目录越出根目录。
- 单次目录列表限制为 500 个项目，避免一个大目录造成过大的响应和浏览器渲染负担。
- WebSocket 创建会话时保留现有路径校验，因此即使客户端伪造 `cwd`，也无法绕过创建边界。

## 验证

- 服务端测试：根目录、子目录和父目录响应；文件过滤；非法路径和根外路径拒绝；指向根外的链接不出现在列表中。
- 服务端测试：响应只包含相对路径，且项目数量受 500 上限约束。
- 浏览器验收：打开选择器、逐层进入、返回上级、确认后创建 PowerShell/CMD，会话状态中的工作目录与选择一致。
- 浏览器验收：在 375px 宽度下路径、目录列表和确认按钮可用且不重叠。
